# Design Goals

Content on this site should be optimized for **reading prose on desktop**. Where possible, pages should **degrade gracefully** on other form factors (such as supporting vertical displays or touchscreens), support screen-readers with aria tags where appropriate, and **print well** directly from the browser. Elements should be padded pleasantly, both from each other and the edge of the screen.

Inspirations include Edward Tufte and Gwern.net.

# Article Defaults

Most content on this site is a single article on a single page.

## Front Matter

An article's front matter (not to be conflated with markdown's `yaml` frontmatter) contains human-relevant metadata about the article. It should begin every article, visually set apart

### Title

The first front matter to appear should be the title, which should be visually more important than anything else in the article.

### Author

The author should appear after the title, less visually notable than most text. It should appear on the same line if the viewport has enough horizontal space, or wrap to its own line otherwise.

### Abstract

The abstract should follow the title and author. It should be formatted similarly to article text, but still stand out at a glance.

## Content

The main content of the article should have a maximum width of 80 characters.

## Colors

There should be three color schemes, dark, light and print. Dark and light color schemes should default to the system preference, based on the css media query `prefers-color-scheme`, but should also be toggleable by the user (see [Navbar](#Navbar)). Once a user sets a theme preference, that preference should be persisted to local storage and reloaded as early as possible in page load.

# Components

## Navbar

### Landscape

On landscape viewports, the navbar sits to the side of the content, right-aligned to its left edge, and is arranged vertically.

### Portrait

On portrait viewports, the navbar is horizontal, in line with the content, before the title. It should match the content's maximum width so they align visually.

### Content

The navbar contains, in order

- A clickable logo that takes you to the homepage
- Links to various internal and external landing pages
- A button that toggles the [Color Scheme](#Colors)

## Table of contents

### Landscape

On landscape viewports, the table of contents should sit to the left of the content, and be arranged vertically, underneath the navbar. As the user scrolls, the top of the table of contents should "stick" to the top of the viewport (with pleasant margin, of course).

The table of contents should have each level be collapsible (so you'd expand a specific `h1` to see `h2`'s under it). Collapse should be controlled by an indicator to the _right_ of that element. A vertical line to the left of siblings groups them together. When a user has javascript enabled, headings should auto-expand and collapse as a user scrolls through the document.

### Portrait

On portrait viewports, the navbar is in line with the content, after the abstract, in a collapsible section. Each level should also be collapsible. Collapse should be controlled by an indicator to the _left_ of that element. All are collapsed by default. This table of contents should _not_ auto-expand and collapse.

## Headings

Hedings should be in a different font from the main content. They should be [anchor links](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/a) to themselves. On platforms with javascript enabled, an icon should appear on hover that copies the full anchor link to the clipboard.

## Links

Links in content should be semi-bold, but not a different color or underlined.

### Popover

Hovering over a link should show a popover, fixed to above the link, with a short preview. The popover can include any html content, but should always have a space for "date published" (which can be unknown) and "date retrieved". The popover should have a fixed maximum size, and can be scrolled if its contents are long.

#### Default Style

By default, links should pull title, author, site/publication name, date and summary from [OpenGraph](https://ogp.me/) tags. Resolution should attempt to fall back to `<title>` and `<meta name="author">` tags if OpenGraph tags are not present.

#### Internal Pages

Internal pages should show the title, abstract, and site name, but not any other information.

#### DOIs

Links to https://doi.org that represent a valid Digital Object Identifier should pull title, author, date published, abstract and other metadata directly from the [CrossRef DOI Api](https://api.crossref.org/swagger-ui/index.html).

#### Wikipedia

Links to Wikipedia should include the title, summary and infobox, as well as an image if one exists.

### Print

When printed, links should appear as regular text. The link originally referenced should be inline-cited in MLA format: e.g. (Author, Year), if the [Bibliography](#Bibliography) is turned on. If not, it should print the full link in plaintext.

## Bibliography

If `bibliography: false` is not set in the frontmatter, the article should include a "Works Referenced" section generated from every link in the article, in MLA style. Entries should be links to their source

#### Additional Citations

Articles can provide an additional list of citations under the `citation` frontmatter property. The list of citations should be in [bibjson](https://rufuspollock-okfn.github.io/bibjson/) format, validated by Astro's support for [frontmatter schema](https://rufuspollock-okfn.github.io/bibjson/).
