# Links

Every link kind the spec describes appears in this paragraph, so a single
selector can reach all four popover styles at once.

## Default Style

An [ordinary external link](https://diff.wikimedia.org/2026/10/02/capturing-essences-with-bolivian-wikimedians/)
resolves through OpenGraph tags, and its popover leads with title, then
metadata, then summary. Its image is wider than it is tall, so it runs across
the top as a banner.

## Internal Pages

A link to the [design specification](/design) shows the title and abstract of the
page it points at, and this site's name — but no author and no date.

## DOIs

A [digital object identifier](https://doi.org/10.1038/s40494-025-02005-1)
carries the full apparatus of a journal article: authors, container title, date
and an abstract.

## Wikipedia

A [Wikipedia article](https://en.wikipedia.org/wiki/Wang_Xizhi) contributes its
short description, a summary, a portrait in a column and an infobox ledger, and
no author line at all.

An article whose image is wide, like [Mount Fuji](https://en.wikipedia.org/wiki/Mount_Fuji),
puts it in a banner instead, and its text runs long enough that scrolling it
shows the banner giving way.

## Unresolved

A [link to a page that is not there](/not-a-page) is classified from its address
like any other internal link, so it keeps the section mark — but nothing
answered at the other end, so the mark is drawn in the attention colour instead
of the machine's own.

# Sidenotes

Two markers set one sentence apart[^first] is the case that matters[^second]:
the notes are long enough that, laid out at their natural positions, they would
overlap. Three in a row[^third] is the same problem with one more term.

## Code

Inline `--color-accent` sits on a faintly tinted ground, and a block of it sits
on the raised surface inside a single hairline:

```scss
@mixin frame-heavy {
    border: 3px solid var(--color-text);
    box-shadow:
        inset 0 0 0 3px var(--color-background),
        inset 0 0 0 4px var(--color-text);
}
```

[^first]:
    The first note runs long on purpose. Its whole job is to occupy more
    vertical space than the gap between its own marker and the next one, so that
    the note below it has to be pushed down rather than drawn on top of it.

[^second]:
    The second note is also long, because a collision needs two
    participants. If these two ever render overlapping, the spec sentence
    "sidenotes that are close together should not overlap, but instead make
    space for each other" has been broken.

[^third]:
    A third note, so that the pushing-down is transitive rather than a
    single special case between one pair.
